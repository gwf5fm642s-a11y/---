задание 1 Создание простого CLI-приложения с аргументами командной строки.
Поскольку платформа 1С:Предприятие не является классической CLI-средой, решение реализовано через связку bat-файла (обертка для командной строки Windows) и конфигурации 1С.
Принцип работы:
Пользователь запускает файл my-cli.bat с аргументами (например, greet Иван).
Bat-файл записывает эти аргументы в промежуточный файл C:\temp\args.txt.
Bat-файл запускает платформу 1С (в фоновом режиме).
В 1С в процедуре ПередНачаломРаботыСистемы срабатывает код: он читает файл args.txt, анализирует команду и записывает результат работы в C:\temp\out.txt, а код возврата — в C:\temp\result.txt.
Bat-файл читает out.txt (выводит результат в консоль) и result.txt (завершается с нужным кодом возврата).

Задание3 Реализация интерактивного и неинтерактивного CLI в 1С
Реализация CLI средствами 1С
Для реализации CLI был создан командный BAT-файл my-cli.bat, который обеспечивает запуск 1С и передачу входных параметров.
Взаимодействие между BAT-файлом и 1С организовано с помощью временных файлов:
- args.txt - передача аргументов командной строки в 1С;
- out.txt - запись результата выполнения;
- result.txt - запись кода завершения программы.
В конфигурации 1С реализована обработка входных аргументов. Она определяет имя проекта, тип проекта, дополнительные опции и наличие подтверждения создания.
Таким образом, BAT-файл отвечает за взаимодействие с пользователем и запуск программы, а 1С — за обработку переданных параметров и формирование результата.

Интерактивный режим
В интерактивном режиме пользователь последовательно отвечает на вопросы программы. Если обязательные параметры не переданы через командную строку, программа запрашивает их самостоятельно.
В ходе диалога реализованы следующие типы вопросов:
- Input  ввод имени проекта;
- List  выбор типа проекта из предложенного списка;
- Checkbox  выбор дополнительных опций;
- Confirm  подтверждение создания проекта;
- Password  ввод пароля администратора со скрытым отображением символов.
После получения ответов программа формирует параметры запуска и передаёт их в 1С для обработки.

Задание 4.Расширенные возможности CLI-интерфейса
Для взаимодействия между BAT-файлом и 1С используются следующие файлы:
args.txt	Передача аргументов в 1С
stdout.txt	Стандартный вывод
stderr.txt	Сообщения об ошибках и предупреждения
result.txt	Код завершения команды
Основная логика CLI реализована на встроенном языке 1С (BSL).
При запуске приложения процедура ПередНачаломРаботыСистемы(Отказ) выполняет следующие действия:
1. Читает аргументы из файла C:\temp\args.txt.
2. Удаляет лишние пробелы и символ BOM.
3. Разбирает переданные параметры.
4. Определяет имя и тип проекта, дополнительные опции и режим выполнения.
5. Выполняет проверку обязательных параметров.
6. Записывает результаты выполнения в stdout.txt.
7. Записывает предупреждения и ошибки в stderr.txt.
8. Сохраняет код завершения в result.txt.
Для записи сообщений используются методы ЗаписатьСтроку() и Записать() объекта ЗаписьТекста.
--name	Имя проекта
--type	Тип проекта
--options	Дополнительные параметры
--confirm	Подтверждение операции
--warning	Демонстрация предупреждения
--error	Демонстрация ошибки
--silent	Тихий режим

Для демонстрации прогресса обработки реализован индикатор Progress Bar.

Разделение стандартного вывода и ошибок
В приложении реализовано разделение потоков вывода:
- stdout используется для отображения результатов выполнения команды;
- stderr используется для предупреждений и ошибок.
1С формирует два отдельных файла: stdout.txt и stderr.txt. BAT-файл выводит содержимое stdout.txt в стандартный поток, а содержимое stderr.txt - в поток ошибок.
Для проверки используется перенаправление стандартного вывода в отдельный файл.
Результат: стандартный вывод можно сохранить в файл, при этом сообщения об ошибках и предупреждениях остаются в терминале.

Реализация принципа Silence is Golden
Принцип Silence is Golden предполагает отсутствие лишнего вывода при успешном выполнении команды.
Для реализации предусмотрен параметр --silent.
При его использовании 1С выполняет обработку команды, записывает код завершения в result.txt, но не формирует обычный пользовательский вывод в stdout.txt.
При успешном выполнении команда завершается с кодом 0. При ошибке возвращается ненулевой код.
Результат: успешное выполнение команды в тихом режиме не сопровождается лишними сообщениями в консоли.

Перенаправление стандартного вывода в файл
Для проверки перенаправления stdout использована команда:
my-cli.bat create --name Test --type Web > C:\temp\result-output.txt
Оператор > перенаправляет стандартный вывод команды в указанный файл.
Для просмотра результата используется команда:
type C:\temp\result-output.txt
В результате файл содержит информацию о созданном проекте. При этом цветовые коды в файл не записываются.
Результат: реализовано сохранение стандартного вывода CLI-команды в текстовый файл.
